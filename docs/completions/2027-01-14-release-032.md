# 2027-01-14 — v0.3.2 release consolidation (Release)

Layer: 2027-01-14 Release. This record consolidates the protocol and core
trust-gate layer of 2027-01-12, the QA fix wave of 2027-01-13 and the earlier
core extraction of 2027-01-11 into one release-facing inventory. It adds no
test, route, header, DTO field, QR parameter, store field, schema field,
signature primitive or v2.2 status. The release is planned as version 0.3.2;
the source at this point still declares version 0.3.1 with code 4 in
`app/build.gradle.kts`, and `RELEASE_NOTES.md` opens with a planned v0.3.2 security-closeout
section followed by the v0.3.1 notes. No tag is applied by this record.

The test figures below are read from the JUnit XML of the last full four-module
run under `protocol/build/test-results/test/`, `core/build/test-results/test/`,
`app/build/test-results/testDebugUnitTest/` and
`harness/build/test-results/test/`. That run recorded 443 protocol + 167 core
+ 254 app + 108 harness = 972 cases with zero failures, zero errors and zero
skipped cases. These counts are historical for the release point. A release
assembly is green after the R8 keep-rule fix described below, so
this record does not claim a green release assembly.

## Release-facing inventory

The protocol module carries 443 cases in the XML, the JVM-only core module
167, the Android shell's JVM unit tests 254, and the in-process CLI harness
108. Earlier totals remain snapshots of their layers: 769 (359 + 323 + 87),
773 (362 + 324 + 87) and the three-module 778 (362 + 324 + 92) are historical
pre-extraction figures; the projected four-module 778 (362 + 112 + 212 + 92)
was a source-level projection until the XML for the new layout existed. The
972 inventory records what the last full run actually produced after the
trust-gate and QA-fix layers. No timing, hardware or device measurement is
attached to any of these numbers.

The release-facing gate set is the one implemented and tested in the two
preceding layers. A prepare offer is bound to the certificate digest that
signed the exact request body, and the app and CLI decide trust with the same
core gate; a JOIN must carry a signed proof bound to the host, circle, invite,
member and five-minute bucket; the shared authority rule never folds JOIN and
folds rekey only for a current owner or admin; panic alerts bind their origin
to a carried origin signature; the direct register route applies the announce
boundary checks; and the relay refuses weak off-box tokens and bounds its
registry. Routes, headers, DTO fields and v2.2 status codes are unchanged.

## Dependency upgrades

The versions declared in `gradle/libs.versions.toml` at this release point are
Kotlin 2.2.0, kotlinx-serialization 1.9.0, kotlinx-coroutines 1.10.2,
Ktor 3.2.2, BouncyCastle 1.87, Netty 4.2.21.Final, slf4j 2.0.17, Android
Gradle Plugin 8.13.2, Compose BOM 2026.06.00, activity-compose 1.13.0,
ZXing 3.5.3 and CameraX 1.4.2. Two entries carry the reason for their floor in
the file itself: BouncyCastle 1.81.1 is affected and 1.87 is published for
both `bcprov-jdk18on` and `bcpkix-jdk18on`, while every Netty module is pinned
to one patch level at or above 4.2.18.Final. `kotlin-reflect` is declared with
the toolchain version so it stays aligned with the compiler rather than a
transitive copy. These are declared dependency facts; the module tests were
run against them in the 972-case rig run.

## R8 keep rules

`app/build.gradle.kts` enables `isMinifyEnabled` and `isShrinkResources` for
the release build and supplies the default Android optimize file plus
`app/proguard-rules.pro`. The app rules keep kotlinx-serialization companions
and generated serializers with their descriptor classes and annotations; keep
`io.netty.**`, `io.ktor.**` and `org.reactivestreams.**` verbatim because R8's
optimized rewrites produced bytecode that device ART rejected during buffer
initialisation; suppress warnings for BouncyCastle classes reached through JCA
servants and OID tables; and list the optional native transport, logging and
compression backends that are guarded at runtime. The packaging block keeps
one copy of each LICENSE and NOTICE path while removing a small set of
duplicate META-INF bookkeeping entries.

The keep-rule fix was made after the earlier release assembly exposed the ART
verification problem. The full rig rerun verified the assembly;
until its result is known, the rules above are recorded as source facts and
the 972 cases as the last full test result, not as a green release build.

## Limitations

- The 972 counts are historical for this release point. The release assembly
  rerun after the R8 keep-rule fix has not produced a result, so no green
  assembly or signing verification is claimed. Without `keystore.properties`
  the release build falls back to the debug key, which is a build-integrity
  check rather than a release-signing verification.
- Version 0.3.2 is planned. The tree still declares 0.3.1 with code 4, the
  release notes still lead with v0.3.1, and no tag is claimed by this record.
- Pin, replay and proof reservations remain process-local and bounded. A
  restart or a separate process has no memory of them, and proof validity is
  limited to the five-minute bucket grid with one bucket of tolerance.
- No physical device walk, carrier transfer, camera decode or larger mesh is
  attached to this release. Mesh claims stay at the three-identity baseline
  and phone-to-phone RFCOMM stays unverified.
- No performance or timing figure is asserted, and no security proof is
  claimed by this record.
