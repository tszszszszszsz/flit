## Release-facing gate rules

- A JOIN must carry one signed event whose body is exactly `{"proof":"…"}`,
  the unpadded Base64URL SHA-256 of a `FLITJOIN1`-tagged, length-prefixed nonce
  bound to host fingerprint, circle id, invite, member fingerprint and a
  five-minute bucket. The host recomputes it and refuses a missing, malformed,
  forged or stale proof before the delegate is called.
- Rekey authority is officer-only. JOIN never folds out of a host answer; REKEY
  folds only for a current owner or admin; ordinary events fold inside their
  own circle. A departing officer cannot hand over the key in the same batch,
  and a forced rotation on departure outranks a same-batch admitted rekey.
- The app verifies a signed event before reserving its id, deduplicates by id
  in canonical order and keeps the batch and log caps, so a forgery cannot burn
  a valid event's id and a replay cannot be folded twice.
- The CLI verifies host answers with `--host-fp`; rotated keys are learned only
  from host-signed REKEY events in the signed log and installed by generation.

## Limitations

- A captured proof is single-use only in-process. The id reservation is kept
  in a process-local bounded set; a restart or another process has no memory
  of it.
- Proof validity is bounded by the five-minute bucket grid; the host tolerates
  one bucket and treats further rollovers as replay. The invite remains a
  bearer credential while it is valid.
- The replay set is process-local and bounded at `MAX_SEEN = 4096`. It is not a
  shared or durable replay store.
- No physical device walk is part of this release. The 2026-12-17 walk remains
  deferred, with rig evidence only and no placeholder observation.
- A larger mesh is unverified. The recorded walks use the small in-process
  identity set; no Circle with more members than the baseline is recorded.
- The release consolidates documentation and metadata only; it adds no test
  and no new evidence beyond the fresh JVM rig named above.
